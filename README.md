把一堆乱七八糟的发票文件（PDF / OFD / XML）丢进一个文件夹，一条命令得到：
**去重后的归档 + 报销汇总表 + 一份可以离线打开的报告。**

```bash
fapiao scan ./我的发票 --archive
```

## 为什么需要它

每个月底报销的人都在重复同样的事：

- 邮箱里、微信里、支付宝里下载的发票，**文件名全是乱码**（`dzfp_25512000000012345678_20260901.pdf`）
- 同一张发票**下载了两次**，自己根本发现不了 —— 而重复报销是财务红线
- 报销前才发现**抬头写错了**，被打回重开
- 手工把金额一张张填进 Excel，**加错一个数字就要全部重来**

现有工具的普遍做法是：把发票图片**上传到云端大模型做 OCR**。这意味着你的
发票（含公司名、税号、消费金额、行程）离开了你的电脑，而且识别结果还带概率误差。

**但这件事根本不需要 AI。** 现在的电子发票（数电票）PDF / OFD / XML 都**自带文本层**，
字段是确定性的，用规则解析可以做到准确、可复现、可验证，而且完全离线。

> 验证方法：断网，工具照样工作；打开任务管理器，全程零网络请求。

## 快速开始

### 1. 安装

```bash
git clone https://github.com/dfhhvc/fapiao-vault.git
cd fapiao-vault
pip install -e ".[pdf,excel]"
```

- `pdf`：解析 PDF 发票（**唯一的第三方依赖**，OFD 与 XML 用标准库即可解析）
- `excel`：导出 `.xlsx`（不装会自动降级为 CSV，功能不受影响）

### 2. Windows 一键运行

双击项目根目录下的 `一键整理发票.bat`（首次运行会自动安装 pypdf）：
**把任意发票文件夹拖到它的图标上**，就会扫描该文件夹；直接双击则扫描 `samples` 示例目录。
扫描完成后会自动打开 HTML 报告。

### 3. 命令行

```bash
# 扫描 + 生成报表
fapiao scan ./我的发票

# 扫描 + 按月份归档重命名（原文件保留，只做复制）
fapiao scan ./我的发票 --archive

# 带上公司抬头，自动检查每张票的抬头和税号是否会报销被退回
fapiao scan ./我的发票 --company "某某科技有限公司" --tax-id "91330100MA2XXXXXX2"

# 校验一个统一社会信用代码是否合法
fapiao verify 91330100MA2XXXXXX2
```

扫描后会生成 `_报表/` 目录：

| 文件 | 用途 |
|---|---|
| `发票报告.html` | **双击即可离线打开**的可视化报告，有搜索、筛选、汇总 |
| `发票汇总.xlsx` | 三个工作表：发票明细 / 报销汇总 / 重复发票 |
| `发票明细.csv` | 带 UTF-8 BOM，Excel 双击不乱码 |
| `台账.json` | 历史台账，下次扫描自动读取，用于发现**跨月重复报销** |

归档结果长这样（自动按月份分目录、自动去重命名、不覆盖已有文件）：

```
_归档/
└── 2026-09/
    ├── 2026-09-01_示例出行有限公司_42.50元_25117000000000000001_普通发票.pdf
    ├── 2026-09-03_示例酒店有限公司_123.60元_25117000000000000002_普通发票.ofd
    └── 2026-09-01_示例出行有限公司_42.50元_25117000000000000001_普通发票_2.pdf   ← 重复件
```

## 它能检查出什么问题

工具在解析后会做这些校验，并把问题写进报告：

- **跨期重复报销（最高风险）**：本次扫描的票号已存在于**历史台账**且月份不同
  —— 这是财务最警惕的场景，会与批内查重分开单独标红
- **重复报销风险（高风险）**：同一张发票号出现在**不同月份**的扫描批次内
- **同一张票重复收集**：同批次内票号相同，或文件内容完全一致（sha256）
- **抬头不符**：购买方名称与你公司的抬头不一致
- **税号错误**：购买方税号与公司税号不符，或**校验位算不过**（GB 32100-2015）
- **金额不勾稽**：金额 + 税额 ≠ 价税合计（超过 1 分钱）
- **大小写金额不一致**：中文大写与小写对不上，这是发票被涂改的信号
- **发票号码格式异常**：数电票应为 20 位且无发票代码；传统票为 12 位代码 + 8 位号码

## 支持的格式与边界

| 格式 | 支持 | 说明 |
|---|---|---|
| PDF（数电票 / 增值税电子发票） | ✅ | 读文本层，无需 OCR |
| OFD | ✅ | **纯标准库解析**（OFD 本质是 ZIP + XML） |
| XML（数电票原件） | ✅ | 结构化字段直读，零误差 |
| 图片（jpg / png / 扫描件） | ❌ | **刻意不做 OCR**，会被识别出来并提示你改用原始电子发票 |

工具只处理**自带文本层的电子发票**。绝大多数来自邮箱、微信、支付宝、电商平台的
发票下载件都属于这一类。真正的纸质扫描件不在射程内——这是刻意的边界，
因为要把它们做对就必须上 OCR，那会破坏"离线 + 确定性"这两个核心承诺。

## 工作原理

```
发票文件
   │
   ├─ .pdf ─→ pypdf 抽取文本层 ─┐
   ├─ .ofd ─→ 解 ZIP，遍历 XML 文字节点 ─┤
   └─ .xml ─→ 直接读结构化字段 ──────────┤
                                          ▼
                              字段抽取（正则 + 版式规则）
                                          │
                     ┌────────────────────┼────────────────────┐
                     ▼                    ▼                    ▼
                 合规校验              三级查重              置信度评估
              （税号校验位/            （票号 →             （字段完整度
               金额勾稽/抬头）          文件指纹 →            + 问题数量）
                                          内容键）
                                          │
                                          ▼
                     归档重命名 + HTML/Excel/CSV/JSON 报表
```

两个值得一提的工程细节：

1. **文本层版式兼容**。数电票的购买方/销售方用纵向标签（购/买/方/信/息），
   PDF 抽取后这些字会与字段值粘连（`…有限公司买`）。工具用"分区切分 + 出现顺序兜底"
   双路径识别，两种版式都有测试样例锁定。
2. **查重不误报**。完全没解析出内容的文件（既无号码也无金额）**不参与**内容级查重，
   否则一堆"解析失败"的文件会被误报成互相重复。

## 隐私承诺

| 承诺 | 你自己怎么验证 |
|---|---|
| 不发起任何网络请求 | 断网运行，或开抓包工具全程观察 |
| 不上传发票内容 | 代码里没有 `requests` / `urllib` / `httpx` 等网络调用 |
| 不改动你的原始文件 | 归档是**复制**不是移动；重名自动加序号，绝不覆盖 |
| 不写注册表、不留后台 | 纯命令行/库，跑完即退出 |

唯一会写文件的地方：你指定的输出目录（默认 `_报表/` 与 `_归档/`）。

## 常见问题

**Q：为什么不用 AI / OCR？**
A：因为没必要，而且代价更高。电子发票自带文本层，规则解析是**确定性**的——同样的输入
永远得到同样的输出，可以写测试，出错能定位到具体规则。OCR 是概率性的，还要求你把
发票图片传给第三方。只有在处理**扫描件**时才需要 OCR，而那不是本工具的目标场景。

**Q：我的发票是图片怎么办？**
A：去开票平台重新下载原始 PDF/OFD/XML 原件（通常免费且即时），比 OCR 更准。
工具会明确告诉你哪些文件属于这一类。

**Q：会不会把我的发票弄丢？**
A：归档只做复制。原始文件从头到尾不会被移动、改名或删除。

**Q：能处理几百张发票吗？**
A：可以。解析是纯本地字符串处理，速度在毫秒级。

## 项目结构

```
fapiao-vault/
├── src/fapiao_vault/
│   ├── models.py          # Invoice 数据模型（金额用 Decimal）
│   ├── fields.py          # 字段抽取：三种文本视图 + 版式规则
│   ├── validate.py        # 税号校验位、发票号码格式、抬头合规、金额勾稽
│   ├── dedup.py           # 三级查重引擎 + 历史台账
│   ├── parsers/           # pdf / ofd / xml 三个解析器 + 调度
│   ├── pipeline.py        # 扫描流水线
│   ├── archive.py         # 归档重命名
│   ├── report.py          # HTML / Excel / CSV / JSON 报表
│   └── cli.py             # 命令行入口
├── tests/                 # 107 个单元测试（标准库 unittest）
├── tools/make_fixtures.py # 合成测试样例生成器
├── samples/               # 生成的测试样例
└── docs/                  # logo 与 README 演示图
```
